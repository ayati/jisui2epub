# jisui2epub

自炊PDF（OCRテキスト層付き）から青空文庫形式テキストとリフロー型ePub3を生成するツール。

紙の本を裁断・スキャン（ScanSnap等）して自動OCRしたPDFから本文を抽出し、
手作業で行っていた以下の校正作業を自動化する:

- **天柱・地柱の除去** — ページ上下に毎ページ繰り返されるタイトル・章名
- **ノンブル（ページ番号）の除去** — 欄外の番号行だけでなく、本文の段落の
  途中に食い込んだ番号（ページ跨ぎ段落への「木24立」のような割り込み）も剥がす
- **ふりがな→ルビ変換** — 座標とフォントサイズからルビを検出し `親文字《るび》` 形式に
- **段落の復元** — 字下げ位置から段落境界を判定（会話文の天付きにも対応）
- **章見出しの検出** — ［＃改ページ］＋［＃「…」は中見出し］マーカー付与（ePubの目次になる）。
  大きな活字の章題、柱と同じ章題、**本文と同じ大きさの章題・章内の節番号・
  天付きの大活字章題**（v1.7.0〜）の各型に対応
- **紙の目次ページとの照合による目次精錬** — 前付けの目次ページを章題辞書として
  章頭見出しと突き合わせ、化けた縦中横の章番号を連番で再構成（ｕ→11、Ⅳ→17）、
  章題の誤字を目次・柱との多数決で修復、取りこぼした章（訳者あとがき等）を回収、
  扉・中扉の書名見出しを降格、目次ページ自体は本文から除去（ePubのnav目次が代替）。
  `--no-toc-refine` で無効化できる
- **目次生成の精度向上（v1.2.0〜）** — 印刷目次を章立ての一次ソースに格上げ。
  目次ページ検出を構造ベース（章序数の連番列・目次ラベル）にして良い目次を
  取りこぼさない／純漢字の章題（四字熟語等）を保護／章扉ページ（章題が改ページに
  挟まれた独立行）を正確な章境界として最優先採用／柱（毎ページの走り出しが
  ノンブル融合で偽見出し化するもの）を畳んで段落分断を解消／巻末の広告・奥付・
  参考文献・著者名などを目次から降格。設計は `DESIGN_目次生成.md`
- **章頭マーカーの検出（v1.7.0〜）** — 「本文と同じ大きさの活字で書かれた章題」
  （`第一章`）や「章の中の節番号」（`１`）を拾う。従来は本文より1.18倍大きい活字か、
  柱と同じ文字列でなければ章と認めていなかったため、こうした本では**章前の改ページ・
  目次項目・ジャンプ先がまとめて落ちていた**。決め手は「章頭マーカーは本の中で
  同じ字下げ位置に繰り返し現れる」という性質。章題がページ天に**天付き**で置かれ
  数列ぶん空けてから本文が始まる型（講談社X文庫等）にも対応する。
  `--no-chapter-marks` で無効化。設計は `DESIGN_章頭改ページ.md`
- **印刷目次のページ数による章題の修復（v1.7.0〜）** — 前付けの目次に並ぶページ数を
  読み取り、ノンブルと突き合わせて章の物理ページを割り出す。OCR が崩した章題
  （`十＝`→`十二章`、`十垂`→`十六章`）を確実な表記に直す。ノンブルが信用できない
  スキャンでは自動的に使わない
- **巻末広告・奥付を目次から締め出す（v1.7.0〜）** — 巻末広告は書名と紹介文を
  段違いに積むため「本文の天から下がって始まる列」が半数を超える。この特徴で
  本文の終わりを判定し、以降の大活字を見出しにしない。印刷目次が読めない本にも効く。
  `--no-backmatter-cut` で無効化
- **章の中の節を目次にぶら下げる（v1.7.0〜）** — 章名のある本で節番号（`１`『２』…）を
  平坦に並べると目次が数倍に膨れるため、直前の章の下に入れ子で表示する。
  章名が読めない本（節番号そのものが章の区切りになる本）は従来どおり平坦な目次になる
- **柱（毎ページの走り）から章立てを作る（v1.10.0〜）** — 柱に章題が入っている本は、
  柱が同じページの連なり（柱ラン）がそのまま章の区間になる。**章頭が全面挿絵の中扉で
  ページの中に章題が1文字も無い本**でも章立てとePubの目次が作れる。柱が書名の本では
  発火しない（`--no-chapter-marks` で無効化）。設計は `DESIGN_柱ラン章立て.md`
- **章頭が挿絵の本の章立て（v1.10.0〜）** — 章の始まりが全面挿絵で、章番号が
  絵の中の囲み数字にしかない本（OCRでは読めない）は、**挿絵ページの現れる間隔の
  規則性**から章頭を選び、出現順に連番を振る
- **重複したテキスト層の畳み込み（v1.10.0〜）** — 元PDFに同じ行が2回入っていると
  1字ずつ噛み合って `騎騎士士道道ととはは何何かか`・`第二二章章` のように壊れる。
  同じ場所に重なった重複を検出して畳む
- **NDLOCRの節番号が2桁に化ける不具合を修正（v1.11.0）** — 裸の算用数字で節を
  区切る本で、ePubの目次が `11 21 44 66` のように壊れていた。認識モデルが
  1文字だけの箱を横に引き伸ばして同じ字を2度読むため。読みの幾何と確信度で補正する
- **段落の字下げが1字になりました（v1.11.0・不具合修正）** — 本文の段落が
  すべて2字下がっていた（章の最初の1段落だけ1字で不揃いでもあった）。
  ePub生成時に段落頭の全角空白とCSSの `text-indent` が二重に効いていたため
- **挿絵OCRノイズの除去** — 挿絵ページから出る記号・珍漢字の羅列を除去
- **本文に混ざる半角ハイフンの全角化（v2.1.0）** — 和文に挟まれた `-` を
  全角ダッシュ `―` に置換する。ISBN・電話番号・型番のように英数字に隣接する
  ハイフンは変換しない
- **OCR系統誤りの後処理正規化** — 文脈から機械的に正せる誤りを自動修正
  （ｌ/Ｉ→ダッシュ――・長音ー、○→数字文脈で〇、〃″→〝〟、拗音の小書きカナ並字化）
- **ルビ誤読の自動訂正** — ルビ内の漢字混入（女《おん姪》→おんな）に加え、
  濁点・半濁点・小書きの誤読（くぴ→くび、ちようめ→ちょうめ）を
  読みの音韻知識＋本内多数決で訂正
- **意図的な改ページの反映** — 章末・章扉・目次・詩など本文が途中で終わるページを
  検出して ［＃改ページ］ を付与。ePubでは目次項目を増やさずに改ページとして描画
- **挿絵・口絵・章頭ページの画像ページ化** — 本文行がほぼ無くインクの多いページを
  検出してJPEG化（余白自動トリム）。テキストには ［＃「挿絵」の図（…）入る］ タグと
  `タイトル_images/` フォルダ、ePubには公式電子書籍と同じ全画面の画像ページとして
  該当位置に綴じ込む（目次は増えない）
- **本文と同居する図・写真の切り出し（v2.2.0〜）** — ページの一部を占める図・写真・
  解説図を**キャプションごと**切り出し、紙面の読み順どおりの位置に挟む。
  従来はページまるごとが絵のページしか画像にできず、**本文と同じページに載る図は
  キャプションもろとも消えていた**（人類の起源は公式ePubの43枚に対し出力0枚）。
  `--inline-figure {auto,strict,off}`・`--figure-dpi`。設計は `DESIGN_部分図.md`
- **見開きの図の連結（v2.2.0〜）** — 2ページにまたがる地図・挿絵を1枚につなぐ。
  綴じ側にインクが接しているかで判定し、縦書き（右綴じ）と横書き（左綴じ）で
  左右の並びを切り替える。`--no-spread` で無効化
- **図のキャプションのテキスト化（v2.2.0〜）** — 図の下のキャプションを拾って
  ePubの `<figcaption>` に出す。画像の中にも入っているが、**焼き込まれた文字は
  拡大できない**ので、リフローで読める形を別に持つ。`--figure-caption off` で無効化
- **罫線でできた図（系図・表・年表）の切り出し（v2.3.0〜）** — 名前が縦書きの
  テキストで並び細い罫線でつながれている図は「テキストの無い矩形」としては
  拾えない。**罫線そのものを検出**して図の位置を決める。
  **本文のテキストは消さない**（構造は画像で、名前はリフローのテキストで残る）。
  `--no-ruled-figure` で無効化
- **底本の空行の反映（v2.4.0〜）** — 段落と段落のあいだに空の列があるページを
  検出して空行として出す。縦組みは右→左に列が詰まるので、隣り合う本文列の
  間隔が1列ぶん空いていれば底本の空行と分かる。場面転換や強調の1行が
  詰まって読めていた箇所が本来の間で読めるようになる。`--no-blank-line` で無効化
- **傍点（圏点）の復元（v2.4.0〜）** — 親文字の右に打たれた点を拾って
  青空文庫の `［＃「…」に傍点］` と ePub の `text-emphasis` で残す。
  **スキャナOCRを直接使うときだけ効く**（再OCRすると点そのものが消える）。
  `--no-bouten` で無効化
- **本文列の欠落の警告（v2.4.0〜）** — スキャナOCRが段落末尾の短い列を
  ルビと誤認して読み崩した箇所を検出して報告する。**復元はできない**ので
  再OCRを促すための警告
- **横書きの本にも対応（`--horizontal`、v0.9.0〜）** — 実用書・エッセイなど
  横書きスキャン本を変換し、横書き（左→右進行）のePubを生成。左揃えの段組
  （2〜4段）は自動で検出して段ごとに読み順へ直列化する（用語集のような
  段流しも、サイドバー併記のレイアウトも対応）
- **書字方向の自動判別（v2.5.0〜、既定ON）** — `--horizontal` を付け忘れても
  横書きの本を自動で見分ける。**確証があるときだけ横書きに倒し、迷えば縦書き**
  （縦組みの本を横書きと誤認すると全損するため）。実測20冊すべて正判定。
  `--vertical` で自動判別を切れる
- **横書きの図の切り出しを作り直しました（v2.5.0）** — 図の見出し帯・凡例・
  キャプションが切り落とされ、1枚の図が2〜3枚に割れていた問題を解消。
  公式ePubの図との形の一致が 103→**159枚**（169枚中）
- **横書きの図の解像度を上げました（v2.5.0）** — 図解書は図が本体で、
  焼き込まれた文字はリフローで拡大できないため、`--horizontal` の
  `--figure-dpi` 既定を 216 に（図の幅 504→756px）
- **横書き本の章立て（v2.5.0）** — 印刷目次のページ数から章の物理ページを
  割り出し、章題は柱から取る。見出し判定も横書きの組版に合わせた。
  図解・気象学入門で公式ePubの章7つと**完全一致**、見出しの再現率 0→73%
- **NDLOCR の横書き対応（v2.5.0）** — `ndlocr_reocr.py --horizontal`。
  横書きの本にも再OCRの受け皿ができた

## 使い方

```bash
# セットアップ（初回のみ）
python3 -m venv .venv
.venv/bin/pip install pymupdf

# PDF → 青空文庫形式テキスト＋ePub（v2.0.0 から ePub 生成が既定）
# ファイル名が「タイトル_著者名.pdf」なら --title/--author は省略可（自動取得）
.venv/bin/python jisui2epub.py タイトル_著者名.pdf

# 表紙は既定でPDFの1ページ目
.venv/bin/python jisui2epub.py 本.pdf --title "タイトル" --author "著者名"

# 青空文庫形式テキストだけが欲しいとき
.venv/bin/python jisui2epub.py 本.pdf --no-epub

# 横書きの本（実用書など）。ePubも横書きになる
# ルビのない実用書は --ruby drop を付けると小さな文字の誤検出ルビを防げる
.venv/bin/python jisui2epub.py 横書きの本.pdf --horizontal --ruby drop

# 出力テキストをエディタで校正したあと、校正済みテキスト＋元PDFからePubを再生成
# （表紙と挿絵画像はPDFから取得）
.venv/bin/python jisui2epub.py 本.pdf --from-text 校正済み.txt

# 前付け・後付け（表紙・目次・奥付）を除外して本文ページだけ変換
.venv/bin/python jisui2epub.py 本.pdf --pages 10-360

# ページ構造のデバッグ表示（1始まりのページ番号）
.venv/bin/python jisui2epub.py 本.pdf --inspect 20,21
```

主なオプション:

| オプション | 説明 |
|---|---|
| `--title` / `--author` | タイトル・著者名。省略時は「タイトル_著者名.pdf」形式のファイル名から自動取得（`_` 優先、次いで `-` で分割）。ファイル名末尾の OCR 方式タグ（`_vision` / `_docai` / `_yomitoku` / `_ocr` / `_scansnap`、大小文字不問・複数可）は著者名から自動除去。「タイトル_方式.pdf」のように著者名を書かない形では著者名なしとして扱う |
| `--publisher 出版社` | 原出版社。ePub の `dc:publisher` に記録し、yomikake ビューアの書誌ブロック「出版社」欄に表示される |
| `--isbn 9784…` | 底本の ISBN。`dc:source`（`urn:isbn:…`）に記録し、yomikake が国立国会図書館サーチ等の書誌検索リンクに使う。`ISBN` 接頭辞・半角/全角ハイフン付きでも可（13桁へ正規化）。**省略時は奥付・裏表紙から自動検出**（下記） |
| `--no-isbn-detect` | ISBN の自動検出を行わない |
| `--date 2016-03-03` | 底本の刊行日。`dc:date` に記録。**省略時は NDL書誌 → 奥付OCR の順に自動取得**（どちらも取れなければ出力しない） |
| `--no-ndl` | 国立国会図書館サーチ（NDL）の書誌照会を行わない |
| `--no-date-detect` | 奥付からの発行日自動検出を行わない |
| `--creator-source ndl` | `dc:creator` の表記を NDL の責任表示に合わせる（既定 `filename`。変更するとしおりキーが変わる） |
| `--title-kana` / `--author-kana` / `--publisher-kana` | 読み（`file-as`）の手動指定。省略時は NDL 書誌から取得 |
| `--description` | あらすじ・内容紹介（`dc:description`）。自動取得はできないので手動指定のみ |
| `--from-text FILE` | 校正済みの青空文庫形式テキストからePubを再生成。挿絵はテキスト隣の `〜_images/` があればそれを、なければPDFから再取得 |
| `-o FILE` | 出力テキストのパス（既定: PDFと同じ場所に `タイトル_著者名.txt`） |
| `--pages 10-360` | 対象ページ範囲。`5,8,10-` のような指定も可 |
| `--ruby drop` | ルビを除去（古いOCRでルビ精度が悪い場合） |
| `--no-indent` | 段落頭の全角空白を入れない |
| `--no-ocr-fix` | OCR系統誤りの後処理正規化を行わない |
| `--no-images` | 挿絵・口絵・章頭ページの画像ページ化を行わない（本文中の図も止まる） |
| `--inline-figure strict` | 本文と同居する図の切り出しを控えめにする（薄い線画やOCR不能な飾り文字を拾わない）。`off` で切り出さない |
| `--figure-caption off` | 図のキャプションをテキストとして出さない（既定は出す・縦書きのみ） |
| `--no-ruled-figure` | 罫線でできた図（系図・表・年表）を画像として残さない。残す場合も本文のテキストは消さない |
| `--no-spread` | 2ページにまたがる見開きの図を1枚に連結しない |
| `--no-blank-line` | 底本の空行（段落のあいだの列アキ）を反映しない |
| `--no-bouten` | 傍点（圏点）を検出しない |
| `--figure-dpi N` | 本文中の図・画像ページのレンダリング解像度（既定 144、`--horizontal` では 216）。出力が大きすぎるときに下げる |
| `--no-chapter-marks` | 章頭マーカー（`第一章`・章内の節番号）の見出し化を行わない |
| `--no-backmatter-cut` | 巻末広告・奥付の見出し化を抑止する処理を行わない |
| `--orientation auto` | 書字方向（既定 `auto`＝自動判別）。`vertical` / `horizontal` で固定 |
| `--horizontal` | 横書きの本として解析（`--orientation horizontal` と同じ）。段組は左揃え2〜4段まで自動分割 |
| `--vertical` | 縦書きの本として解析（自動判別を切る） |
| `--no-epub` | ePubを生成せず青空文庫形式テキストだけを出力する（v2.0.0 から ePub 生成が既定。既定では書誌照会のため国立国会図書館サーチに接続する。`--no-ndl` で無効化、オフラインなら自動で続行） |
| `--toc-front` | ePubの目次ページを表紙の直後に置く（既定は本文の後・奥付の前） |
| `--no-front-image` | 巻頭の扉・口絵・目次・地図・献辞をそのままの画像として残す処理を行わない（v1.11.0 と同じ扱い） |
| `--cover-page N` | ePub表紙にするPDFページ（既定=1ページ目、`0`で表紙を自動生成） |
| `--cover-image FILE` | 表紙に任意の画像（JPEG/PNG）を使う |
| `--inspect N` | ページ解析結果を表示して終了（チューニング用） |
| `--version` | バージョンを表示して終了 |

### 章構成の検出（v1.7.0〜）

「章の前で改ページされない」「章が目次に出ない」の実体は、**章頭マーカーの
検出漏れ**でした。見出しを立てる直前には必ず改ページが入るので、
**マーカーさえ拾えれば改ページ・目次項目・ジャンプ先が同時に戻ります。**

拾える型を3つに増やしました。

| 型 | 例 | 決め手 |
|---|---|---|
| 本文と同じ大きさの章題 | `第一章`（伯爵夫人は超能力・集英社文庫） | 本の中で**同じ字下げ位置**（本文の天から3.4字）に14回繰り返し現れる |
| 章の中の節番号 | `１`（風の万里黎明の空・新潮文庫） | 同じく字下げ位置が揃う（27箇所すべて天から4.0字）。1文字なので従来はノンブルとして捨てられていた |
| 天付きの大活字章題 | `十章`（風の万里黎明の空 下・講談社X文庫） | ページの一番右に**天付き**で置かれ、次の本文列まで**6列ぶん空く**（＝「空行があってから本文」） |

いずれも「書籍全体で3件以上そろったときだけ採用」します。印刷目次のページや
挿絵の罫線ノイズを1件だけ拾って本文構造を壊さないための条件です。

**印刷目次のページ数を章題の修復に使います。** 縦組みの目次はページ数が
桁の切れ目なく1本の文字列として読み取られますが（`369361343318296273239210`）、
章のページ数は単調なので分割は一意に戻せます。ノンブルとの差を取れば章の
物理ページが分かり、OCR の崩れた章題を目次の表記に直せます。

風の万里黎明の空 下（387ページ・全13章）の実測:

| | v1.6.0 まで | **v1.7.0** |
|---|---|---|
| 目次に出る章 | 0 | **13（全章）** |
| 章題の表記 | — | `十章（承前）`〜`終章`（`十＝`→`十二章` 等3件を目次で修復） |
| 巻末広告の混入 | 7件 | **3件** |

伯爵夫人は超能力では全14章＋登場人物ページ後の改ページが戻り、
風の万里黎明の空 上では27の節番号と改ページが出るようになりました。
地下室からのふしぎな旅・書を捨てよ町へ出よう・蘇我氏でも、
これまで落ちていた章が目次に出ます。

**目次に何も足さない本もあります。** ノンブルが読めないスキャンでは目次の
ページ数を使いません（誤った位置に章を立てるより無害なため）。章題そのものが
画像で、テキスト層に文字が無い章扉ページも読めません。

### 柱から章立てを作る（v1.10.0〜）

これまでの見出し検出はすべて「章題がページの中に読める形で存在する」ことが前提でした。
そのため**章の始まりが全面挿絵の中扉で、章題が柱（毎ページ上部の走り）にしか無い本**は、
章立てが原理的に作れませんでした。

柱の出現ページを連続区間（柱ラン）に割ると、ページの中を一切読まずに章の地図が戻ります。

| 本 | v1.9.0 まで | **v1.10.0** |
|---|---|---|
| 天久鷹央の推理カルテ（実業之日本社文庫・302P） | 1 | **7（公式ePubと同じ全章）** |
| 三国志（五）（吉川英治・496P） | 25 | **40** |
| 黒牢城（米澤穂信・525P） | 1 | **8** |
| 百億の昼と千億の夜（光瀬龍・477P） | 10 | **11**（欠けていた序章が復活） |
| ぼくがぼくであること（山中恒・339P） | 0 | **15（公式ePubと同じ 1〜15）** |

**柱が書名の本では発火しません。** 「柱が章題なら、章の区間は互いに重ならず本文全体を
敷き詰める」という組版の性質をそのまま条件にしているためです（図南の翼は柱が書名で、
1文字ずつ割れて4つのランが立ちますが、本の8%しか埋めないので不採用になります）。
**既に章立てができている本にも手を出しません**（既存の見出しがラン数以上なら見送り）。

章の始まりが全面挿絵で章番号が絵の中の囲み数字にしかない本（OCRでは読めない）は、
**挿絵ページの現れる間隔の規則性**から章頭を選び、出現順に連番を振ります。

### 目次の先頭が「第1話」でなくなりました（v1.10.0・仕様変更）

最初の章見出しより前の部分に付けていた **`第1話` という目次名を廃止**しました。

この部分の中身は本文ではなく**前付け**（口絵・扉画像・書名の扉）で、
「第1話」は話数形式でない本の目次で浮きます（`第1話` → `第一章` → `第二章`）。
中身を見て呼び分けます。

| 中身 | 目次名 | 例 |
|---|---|---|
| 画像だけ | **口絵** | タイム・リープ上（口絵3枚）・黒牢城・地下室・書を捨てよ |
| テキストを含む | **扉** | グリック（挿絵2枚＋書名）・ほんもの・風の万里・ソフロニア |
| 章見出しが1つも無い本 | 書名 | （従来どおり） |

```
表紙                          表紙
タイトルページ        →      タイトルページ
目次                          目次
第1話                         口絵
序章はじまりとおわり           序章はじまりとおわり
```

前付けが空の本（霧・蘇我氏・伯爵夫人など）は従来どおり目次に何も出ません。
**テキスト出力（.txt）は変わりません**。ePubの目次だけの変更です。

### 重複したテキスト層の畳み込み（v1.10.0〜）

元PDFのテキスト層に**同じ行が2回入っている**ことがあります。両方を1行にまとめるため
1字ずつ噛み合い、次のように壊れていました。

```
騎騎士士道道ととはは何何かか      ← 正しくは「騎士道とは何か」
第二二章章マシュクスバートの驚き   ← 正しくは「第二章マシュウ・クスバートの驚き」
長方形形のの墳墳丘丘にに、、      ← 正しくは「長方形の墳丘に、」
```

同じ場所に重なった重複を検出して畳みます。**約物と数字は対象外**です
（`……` `･･` やノンブルの `122` は縦組みで詰めて組まれるため、連続すると
正当に重なるので、畳むと本文が消えます）。

### 段落の字下げが1字になりました（v1.11.0・不具合修正）

ePubの本文の段落が、**本来1字下げのところ2字下がっていました**（v1.10.0 まで）。
青空文庫形式のテキストは段落頭に全角空白「　」を置きますが、ePubのCSSも
`text-indent: 1em` で1字下げていたため、二重にかかっていたのが原因です。

さらに、章の**最初の1段落だけは1字下げ**になっており、同じ本の中で不揃いでもありました。

ePub生成時に段落頭の全角空白を1つだけ落とすようにしました。
落とすのは1つだけなので、より深い字下げの相対関係は保たれます。
`［＃ここからN字下げ］` ブロックの中は元から二重になっていないので変わりません。

**テキスト出力（.txt）は変わりません**。既存のePubは `--from-text` で
作り直せば直ります（再OCRは不要です）。

### 本文の中の図・写真を残す（v2.2.0〜）

`classify_image_pages`（従来）はページ単位でしか動かないため、**本文と同じページに
載っている図は、キャプションも図中の文字も丸ごと落ちていました**。

```
人類の起源（中公新書）  公式ePubの本文中の図 43枚 → v2.1.0 の出力 0枚
星空をつくる機械        公式ePubの本文中の図 81枚 → v2.1.0 の出力 0枚
```

v2.2.0 は「本文の縦行に覆われていない矩形」を図の領域として切り出します。
縦組みの本ではキャプションが横組みなので、この矩形の中に自動的に入ります。

| 本 | 本文中の図 | キャプション | 見開き |
|---|---|---|---|
| 人類の起源 | 43枚 | 31件 | — |
| 星空をつくる機械 | 71枚 | 39件 | — |
| 蘇我氏 | 68枚 | 26件 | 7組 |
| グリックの冒険 | 95枚 | 4件 | 1組 |
| シナリオのためのファンタジー事典（横書き） | 696枚 | — | 2組 |
| 伯爵夫人は超能力（図のない小説） | **0枚** | — | — |

副産物として、**ページまるごとが図なのに画像にならなかったページ**も拾えます
（新書のように本文が詰まった本ではインクの基準が高くなり、線画のページが
相対的に薄く見えて落ちていた）。10冊で消えた画像ページは0・追加11ページ。

**罫線でできた図（v2.3.0〜）**: 系図・表・年表のように名前が縦書きのテキストで
並び細い罫線でつながれている図は、名前が本文行として扱われるため上の方法では
矩形ができません。**罫線そのものを検出**して位置を決めます
（文字のグリフは長い連続した直線を作らないが罫線は作る。実測で蘇我氏の本文ページは
罫線0本、系図・表は8〜38本）。**このときも本文のテキストは消しません**——
系図の名前は罫線が化けた形（`庁`・`ｌ`）でも現状すでに本文に出ており、消すと
拡大して読める形が失われるためです。構造は画像で、名前はリフローのテキストで残ります。

**横書きの本ではキャプションを拾いません**（図解書はキャプションを図の中に
組み込むため、「図の下の行」という構造が無い）。

`タイトル_images/` を消しても、**矩形をファイル名に持たせてある**ので
`--from-text` で PDF から同じ切り抜きを再現できます。

### 横書きの本の作り直し（v2.5.0）

図解実用書（講談社ブルーバックス『図解・気象学入門 改訂版』）を公式ePubと
突き合わせて、横書き経路をひととおり作り直しました。**本文は元から 97.7%
取れており、落ちていたのは文字ではなく構造でした。**

| | v2.4.0 | v2.5.0 |
|---|---|---|
| 公式ePubの図169枚との形の一致 | 103枚 | **159枚**（図なし0） |
| 切り出した図の総面積 | 6.39M pt² | **10.47M pt²** |
| 図の解像度（幅の中央値） | 504px | **756px** |
| 章（公式ePubは7章） | 0 | **7/7**（位置・題とも一致） |
| 見出し（公式ePub 145件との一致） | ほぼ0 | **106件**（再現率 73%） |
| 本文再現率 | 97.65% | 97.65%（不変） |

**図が刻まれていた理由**は横書き固有でした。縦組みでは図中のラベルや
キャプションは横組みなので自動的に区別できますが、**横書きの本では図中の
文字も本文と同じ向き**なので、図の候補が「ラベルとラベルのすき間」だけに
なっていました。本文の行送りの**梯子**に乗る行だけを本文とみなすことで解決
しています。歯止めが4つ要りました（行送りは書籍レベルで測る／行頭から
始まらない行は載せない／長い行を2本以上要求する／段組の同型判定）。詳細は
`DESIGN_部分図.md` §14・§15。

**章立て**は印刷目次から作ります。横書きの目次は「節題 → ページ数」が行単位で
読めるので、ノンブルのオフセットを足せば章の物理ページが分かります
（縦組みではページ数が漢数字ジャンクになるので使えませんでした）。
章題は柱から取ります——目次側は飾りタイルを巻きこんで崩れますが、
柱は丸数字だけが壊れるためです。詳細は `DESIGN_横書き章立て.md`。

### 書字方向の自動判別（v2.5.0〜、既定ON）

`--horizontal` を付け忘れても横書きの本を自動で見分けます。

```
$ .venv/bin/python jisui2epub.py 図解の本.pdf
書字方向: 横書きと判定（横票率 0.98 / 行長 縦20・横26） — --vertical で無効化できます
```

**誤りの重さが非対称**なので「迷ったら縦書き」に倒します。縦組みの本を
横書きと誤認すると転置座標で本文・章立て・図が全損しますが、逆は従来どおり
（`--horizontal` を付ければ直る）で済むからです。

判定は書籍単位で、独立した2つの信号が揃ったときだけ横書きにします。

- **向き票** — スパンの縦横比。実測20冊の横票率は縦書き 0.00〜0.15 /
  横書き 0.93〜1.00。**票が立たないのは縦組みの本だけ**（PyMuPDF は
  同じ行に並ぶ文字を1スパンにまとめるので、再OCR済みでも横組みなら票が立つ）
  という非対称性があり、票率の低さ自体が縦書きの証拠になります
- **行長** — 両向きにクラスタリングしたときの1行あたりの文字数。
  紙面の幾何という独立した根拠です（**単独では使えません**——2〜3段組の本は
  横の行が短く、縦23 対 横20 と逆転します）

実測20冊すべて正判定で、オプション無しの出力は `--horizontal` 明示時・
従来の縦書き出力と **1行も違いません**。設計は `DESIGN_書字方向の自動判別.md`。

### 底本の空行・傍点の反映（v2.4.0〜）

紙面には出ているのに、これまで出力に残らなかったものを2つ拾います。

**空行**: 縦組みは右→左に列が詰まるので、**段落と段落のあいだに空の列がある**
のがそのまま底本の空行です。隣り合う本文列の間隔が行送りの1.6倍を超えたら
空行として出します（ePubでは `<p class="body-blank">`）。

グリックの冒険 p264 の「そこに、海が、あったのだ！」は、紙面では前後を1行ずつ
空けて置かれています。公式ePubも同じ位置に空行を入れており、v2.4.0 の出力も
一致します。公式ePubの空行位置と照合して**適合率89%・再現率77%**でした。

**直前の列が下端まで達しているときは空行にしません**。列が丸ごと空くもう一つの
原因は「スキャナOCRが段落末尾の短い列を読み損なった」で、そちらは段落の途中
なので下端まで届きます。章扉（大きさの違う飾り行を離して並べる）と巻末広告
（別組み）も対象外です。`--no-blank-line` で止められます。

**傍点（圏点）**: 縦組みの傍点は親文字の右に打つ小さな点で、ルビと同じ帯に
入ります。スキャナ内蔵OCRはこれを本文の0.3倍級の「、」として拾うので、
その点を親文字に割り当てて青空文庫の `［＃「…」に傍点］` として出します
（ePubは `text-emphasis-style: filled sesame`）。`--no-bouten` で止められます。

**2点以上の連なりだけを採ります。** 孤立した1点はOCRノイズと区別できません。
公式ePubの傍点位置と文字単位で照合した実測:

| 本 | 発行 | 完全一致 | 正しいが短い | 一部ずれ | 明確な誤り |
|---|---|---|---|---|---|
| グリックの冒険 | 169 | 70.4% | 4.7% | 11.2% | **0.6%** |
| ソフロニア嬢 | 126 | 54.0% | 20.6% | 1.6% | **4.0%** |
| 百億の昼と千億の夜 | 25 | 72.0% | 12.0% | 4.0% | **0.0%** |

傍点の無い本での誤発行はほぼゼロです（人類の起源0・蘇我氏0・霧1・伯爵夫人1）。

**ただし、傍点は再OCRすると消えます。** Vision・NDLOCR はいずれも点そのものを
返しません（グリックの冒険で ScanSnap 468点 → NDLOCR 0点）。傍点を残したい本は
スキャナOCRのまま変換してください。

### 本文列の欠落の警告（v2.4.0〜）

スキャナ内蔵OCRは、**段落の最後の2〜3字だけが入った短い列**を「隣の列に付いた
ルビ」と誤認し、ルビ用の小さい認識器で読んで文字化けさせることがあります。

人類の起源 p165 では、印刷の「です。」がテキスト層では 6.3pt の `戸」←９０`
（本文は 12.6pt）になっており、本文が「考えるほうが合理的」で切れていました。

**テキスト層に正しい字が無いので復元はできません。** できるのは気づかせることだけ
なので、列グリッドの空きスロットからこれを検出して件数とページを報告します。

```
⚠ 本文列の欠落疑い: 8 箇所（p22/p79/p113/p165/p240/p269/p312/p314）
  — スキャナOCRが段落末尾の短い列をルビと誤認しています。再OCR（vision/docai/yomitoku/ndlocr）を推奨します
```

再OCRすれば直ります（同じ本を YomiToku で再OCRすると 8箇所 → 2箇所、
赤毛のアンは NDLOCR で 14箇所 → 1箇所）。

### ISBN の正規化と自動検出（ePub生成時）

`--isbn` を省略すると、**奥付・裏表紙バーコードの OCR テキストから底本の ISBN を自動検出**して
`dc:source`（`urn:isbn:…`）に記録します。yomikake ビューアはこの値で国立国会図書館サーチを引くため、
`ISBN` 接頭辞やハイフンは自動で落として**13桁の ISBN-13** に揃えます（ISBN-10 の旧奥付は13桁へ換算）。

- 走査するのは**末尾25ページ**（見つからなければ先頭5ページも）。`--pages` で範囲を絞っていても、
  検出は PDF 全体の末尾を見ます。追加コストは 525 ページの本で 0.25 秒程度です。
- 裸の EAN-13（`978`/`979` 始まり）を優先し、次に「ISBN」表記の直後にある ISBN-10 を探します。
  チェックディジット検証を必ず通すので、価格コードや OCR ノイズは採用されません。
- `--isbn` を明示した場合はそちらが優先されます。値が ISBN として不正なときは警告して自動検出に回ります。
- 自動検出したくないときは `--no-isbn-detect`。

1981年より前の刊行物には ISBN 自体がありません（当時の角川文庫は `0197-216502-0946(0)` のような
分類コード）。また奥付の OCR が壊れていると検出できません。実測 26ファイル中20件検出、誤検出0件です。

### 書誌情報の自動補完（NDL・奥付）

ISBN が分かると、**国立国会図書館サーチ（NDL）から書誌を引いて ePub に載せます**（既定ON・`--no-ndl` で無効化）。
OCR やファイル名では得られない情報が入ります。

| ePub に入るもの | 取得元 |
|---|---|
| 書名・著者名の読み（`file-as`） | NDL（`--title-kana` / `--author-kana` で上書き可） |
| 訳者・画家・編者（`dc:contributor` ＋ 役割 trl/ill/art/edt） | NDL の責任表示 |
| 出版社（`dc:publisher`） | `--publisher` > NDL |
| 刊行日（`dc:date`） | `--date` > NDL > 奥付OCR |
| シリーズ・巻（`dcndl:seriesTitle` / `dcndl:volume`）、分類（`dc:subject` NDC） | NDL |

- **著者名（`dc:creator`）はファイル名・`--author` のままにします**。yomikake のしおりは
  「書名＋著者名」で本を識別するため、ここが変わると既存のしおりが読めなくなるからです。
  訳者や画家は `dc:contributor` に入れます（`--creator-source ndl` を指定したときだけ NDL 表記に変わります）。
- 刊行日は NDL が年月までしか持たないことが多いので、**奥付が同じ年月の日まで読めていれば日付を合成**します
  （NDL `2004-12` ＋ 奥付 `15日` → `2004-12-15`）。食い違うときは NDL を優先します
  （奥付OCRは初版でなく後刷の日付を拾うことがあるため）。
- オフライン・未ヒット・タイムアウトは警告を出して**そのまま変換を続けます**。
- 引いた書誌が明らかに別の本（書名も著者も一致しない）の場合は、警告して NDL の情報を使いません
  （`--isbn` の打ち間違い対策）。
- 実測 20冊すべてで NDL 書誌を取得できました。**あらすじだけは NDL にも無い**ので `--description` で手動指定します。

奥付は ePub の巻末にも反映され、判明した出版社・発行日・ISBN が底本情報として並びます。

### アクセシビリティ metadata

EPUB Accessibility 1.1 / schema.org の項目を自動で付けます。リフロー型テキストなので
`accessMode=textual`（挿絵ページがある本は `visual` も）・`accessModeSufficient=textual`、
機能として `displayTransformability`（文字サイズ変更可）`readingOrder` `structuralNavigation`
`tableOfContents`、ルビを出力していれば `rubyAnnotations` を宣言します。

## 再OCR前処理 — 古いOCRの精度を底上げ

クラウド2種（Vision / Document AI）とローカル2種（YomiToku / NDLOCR-Lite）の
4つのバックエンドがある。**選び方は[この節](#4つの再ocrバックエンドの選び方)**を参照。

スキャナ内蔵OCR（特に古い機種）は文字化けが多く、jisui2epub.py の抽出精度の
上限になっている。`vision_reocr.py` は Google Cloud Vision API でPDFを再OCRし、
より高精度な透明テキスト層に差し替える前処理ツール（jisui2epub.py本体は無改造）。

```bash
# セットアップ（初回のみ）
.venv/bin/pip install google-cloud-vision

# Google Cloudの準備:
#   1. GCPプロジェクトを作成し、Vision APIを有効化
#   2. 課金を有効化（少数ページのテストなら月1000ユニットの無料枠に収まる）
#   3. サービスアカウントキー（JSON）を発行
export GOOGLE_APPLICATION_CREDENTIALS="/path/to/key.json"

# 再OCR実行（既定出力は <入力>_vision.pdf）
# 二段OCR（極小ルビ回収）用にPillowも入れておく（任意。無ければ自動で無効化）
.venv/bin/pip install Pillow
.venv/bin/python vision_reocr.py 本.pdf

# 途中で中断した場合、続きのページから再開できる
.venv/bin/python vision_reocr.py 本.pdf --start 150

# 数ページだけ試す
.venv/bin/python vision_reocr.py 本.pdf --start 10 --end 20 -o test.pdf

# 再OCR後のPDFをjisui2epub.pyにかける
.venv/bin/python jisui2epub.py 本_vision.pdf --title "タイトル" --author "著者名"
```

本文とルビは異なるフォントサイズ（本文の約半分）で書き戻されるため、
jisui2epub.py本体のルビ検出・柱ノンブル除去はそのまま機能する。

Visionが検出漏れする高さ3pt級の極小ルビ（手《て》等）は、**二段OCR**が
該当領域だけを切り出し4倍拡大して自動回収する（文字は旧OCR・位置は
Vision実測のハイブリッド書き戻し。`--no-ruby-rescue` で無効化）。
追加のAPIユニットは欠落領域をタイル画像にまとめて送るため数%程度。
使用ユニット数は実行中・完了時に必ず表示される（無料枠は月1000ユニット）。

### 本文ギャップ救済（v1.1.0〜、既定ON）

Vision APIは、**改行で次の行頭に送られた文の続き1〜3文字**
（「…戦のない土地はな｜**く、**」の「く、」）や**段落頭のダッシュ「──」**を、
画像に鮮明に印字されていても丸ごと返さないことがある（本との相性で発生量が
桁で変わり、実測では黒牢城で177箇所/525ページ、他の4冊では0〜5箇所）。
切り出し・拡大・OCRモード変更のどれを試してもVisionは同じ文字を返さないため、
**旧OCR層をアンカーに欠落を検出**し（追加API不要）、欠落のあるページだけ
Document AIで再OCRして欠落文字を回収する。

- `--gap-rescue auto`（既定）: Document AIが使える環境（google-cloud-documentai
  導入済み＋OCRプロセッサ作成済み）なら欠落ページだけDocAIで再OCR
  （**$1.50/1000ページの従量課金**。多発本の黒牢城でも約100ページ＝約$0.15、
  きれいな本は0〜3ページ）。使えなければ旧OCRの文字をそのまま補完
- `--gap-rescue old`: 常に旧OCRの文字で補完（無料。「ぐ、」のように化けている
  ことがあるが、文が無言で欠けるより校正で発見しやすい）
- `--gap-rescue off`: 回収しない（従来動作）

回収の内訳（どの欠落をDocAI/旧OCRどちらで埋めたか）は実行ログと完了時の
集計に表示され、DocAIの課金ページ数も必ず報告される。

ルビの親文字への対応付けは、正解テキストとのルビペア単位の実測で
74〜92%（ルビ密度が非常に高い児童書・新書4冊で検証。詳細はCLAUDE.md）。
v0.4.0 のルビ読み自動訂正＋約物誤判定修正で、地下室からのふしぎな旅の
全文一致率は83.1%→86.0%（既存の再OCR済みPDFのまま）、再OCRから
やり直すと同一範囲の実測で88.8%→91.6%まで改善した。
v0.6.0 では「親ずれ」（背中《せなか》→中《せなか》のような親文字範囲の
1文字ずれ・別語のルビ誤結合）の幾何計算上の主因2つを修正し、公式ePubの
文字単位ルビを正解にした厳密一致の実測で、親範囲の誤りが
霧のむこうのふしぎな町53→11件・蘇我氏450→360件・地下室102→71件まで減少
（読み自体のOCR誤りは対象外・全冊で章見出しと画像ページは不変）。
v0.7.0 ではさらに、旧OCRがルビのbbox自体を±1セルずれて申告するケースに
「シフト・トゥ・フィット」（隣接する漢字連続への窓ずらし再配置）と
「本内多数決による親拡張」（背｜中《せなか》を本内の背中《せなか》との
照合で修復）の2段構えで対処し、親範囲の誤りは地下室71→29件・
蘇我氏360→324件まで減少（厳密一致率は地下室77.5%・蘇我氏55.0%）。
残る誤りの主因はVision API自体の極小ルビの読み取り精度と
読み文字列そのもののOCR誤りで、
出力テキストの校正時にルビを重点的に確認するとよい。

### さらに高精度を求める場合（docai_reocr.py）

`docai_reocr.py` は同じ仕組みのOCRエンジンを Google Cloud **Document AI**
（Enterprise Document OCR）に差し替えた版。**無料枠がなく$1.50/1000ページ**
（300ページの本1冊≈70円）かかるが、実測で本文の誤読がVisionより少なく
（地下室からのふしぎな旅10ページの本文でVision誤り42字に対しDocAI30字・
うち実質的な誤読は1字のみ。残りは字種の揺れとノンブル混入）、Visionが
検出漏れする1文字だけの極小ルビも自前で検出できる。処理速度は約2秒/ページ
（Visionの約4倍遅い）。

```bash
# セットアップ（初回のみ）
.venv/bin/pip install google-cloud-documentai
# Google Cloud ConsoleでDocument AI APIを有効化（課金必須）した上で、
# OCRプロセッサを作成する:
.venv/bin/python docai_reocr.py --create-processor

# 使い方はvision_reocr.pyと同じ（既定出力は <入力>_docai.pdf）
.venv/bin/python docai_reocr.py 本.pdf
.venv/bin/python docai_reocr.py 本.pdf --start 10 --end 20 -o test.pdf
```

まずは無料のvision_reocr.pyを試し、誤字の多さが気になる本にdocai_reocr.pyを
使う、という使い分けを推奨。

### クラウドを使わない場合（yomitoku_reocr.py）

ルビが語単位でまとまって返るためVision特有のルビ誤結合が起きにくく、

### 完全無料・商用利用も可の場合（ndlocr_reocr.py）— 本文向け・ルビは発展途上

`ndlocr_reocr.py` は国立国会図書館NDLラボの
[NDLOCR-Lite](https://github.com/ndl-lab/ndlocr-lite)（**CC BY 4.0**）に
差し替えた版。**完全オフライン・無料・GCP不要**な点は YomiToku と同じで、
さらに**ライセンスが商用利用も許す**のが最大の違い。CPUだけで動く。

導入手順は **[NDLOCR導入ガイド（Windows向け）](README_NDLOCR.md)** を参照。
Linux/macOS なら次の3行で済む。

```bash
# セットアップ（初回のみ）。NDLOCR-Lite 本体は同梱していないので自分で取得する
git clone https://github.com/ndl-lab/ndlocr-lite
.venv/bin/pip install onnxruntime opencv-python-headless numpy PyYAML pillow

# 実行（既定出力は <入力>_ndlocr.pdf）
.venv/bin/python ndlocr_reocr.py 本.pdf --ndlocr-dir /path/to/ndlocr-lite
```

`--ndlocr-dir` は環境変数 `NDLOCR_DIR` でも指定できる。`--start` / `--end` /
`--preprocess` は他のバックエンドと同じ。

**横書きの本にも使える（v2.5.0〜）。** `--horizontal` を付ける（既定は
ページごとの自動判定、`--vertical` で縦組み固定）。**4つの再OCRバックエンドの
うち横書きに対応しているのは現在これだけ**で、他の3つは縦組み専用のまま。

```bash
.venv/bin/python ndlocr_reocr.py 図解の本.pdf --ndlocr-dir /path/to/ndlocr-lite --horizontal
```

実測（『図解・気象学入門 改訂版』322ページ・ScanSnap 内蔵OCR との比較）:

| | ScanSnap 直変換 | NDLOCR（横書き） |
|---|---|---|
| テキスト層の素の精度（p12-20） | 99.03% | **99.76%** |
| 本文再現率（公式ePub照合） | 97.65% | **98.64%** |
| ルビ適合率 | 40.2% | **80.7%** |
| 見出し（公式ePub 145件との一致） | 106件（73%） | **126件（87%）** |

節番号（`1-1`。ScanSnap は飾りタイルを `趾` に化けさせる）が読め、
見出し先頭のアイコンノイズが消え、ルビが語ごとに分かれます。

**NDLOCR が返す分類（`line_title` / `block_pillar`）を活かすのが要点**でした。
一律のサイズで書き戻すと「見出しは大きい活字」という情報が消えて
**章立てが丸ごと落ちます**（見出し 140→52 になるのを実測）。見出しは本文の
1.25倍で書き戻し、本文より太い箱は柱扱いしません。詳細は
`DESIGN_NDLOCR横書き.md`。

**⚠️ NDLOCR-Lite の `requirements.txt` は使わないこと。** 上の1行で足りる。
本家の requirements は本家GUI用の依存（`flet` 等）まで含むうえ全版がピン留めで、
**`numpy==2.2.2` に Python 3.14 用の wheel が無いためソースビルドに落ち、
Windows では `Microsoft Visual C++ 14.0 or greater is required` で止まる**
（実機で報告あり）。jisui2epub が呼ぶのは `deim.py`（検出）と `parseq.py`
（認識）だけで、その依存は onnxruntime / opencv / numpy / PyYAML / **Pillow**
の5つ。PDFの読み書きは jisui2epub 側の PyMuPDF が担当する。
**Pillow は必須**（`deim.py`・`parseq.py` が `from PIL import Image` する）。

**⚠️ NDLOCR-Lite を置くパスに日本語（全角文字）を含めないこと。** 本家の
制限で、全角文字を含むと起動しない。`ndlocr_reocr.py` は起動時に検査して
エラーメッセージを出す。

#### 現在の実力（正直なところ）

**本文は実用水準に達しているが、ルビはまだ Vision に届かない。**

| | 本文（往復後の再現率・地下室12頁） | ルビ適合率 |
|---|---|---|
| Vision | 98.79% | 88.8%（地下室）|
| **NDLOCR** | **98.09%** | **65.2〜80.1%**（6冊） |

NDLOCR-Lite は**ルビ（`block_rubi`）の位置は返すが文字を読まない**設計なので、
ルビの切り出し・認識・書き戻しは jisui2epub 側の自作になる。ここがまだ弱い。
6冊での実測は 地下室80.1% / 蘇我氏74.4% / グリック74.3% / 霧71.8% /
黒牢城65.2%（ソフロニアはルビが少なすぎて測定不能）。

> **2026-08 の改善（この6冊は再測していないので上の数値は改善前）**:
> ルビ列を語に切る処理が「1画素でも暗ければインク」でノイズに弱く、
> 語間の空白が埋まって**隣の語と結合していた**（自我即空《じがそくくう》＋
> 色即是空《しきそくぜくう》→ 1語）。インク判定と語間しきい値を較正し直し、
> 新サンプル3冊で 百億 54.6→**63.8%** / ぼくがぼくであること 85.8→86.8% /
> 三国志（五）74.2→74.5%（本文再現率・章立ては不変）。
> **外来語カタカナルビ・梵語・固有名詞が密な本は依然 Vision が確実**
> （百億は素のスキャナOCRの69.0%にも届かない。原因は稀用漢字を似た字に
> 置き換える誤りが親文字側にも出るため）。

- **本文だけ再OCRしたい／ルビの無い本なら現時点でも十分**（`--no-ruby` で
  ルビ後段を止められる）
- **ルビの多い本（児童文学・新書）では Vision のほうが確実**
- **時代小説・古典には向かない。** 黒牢城では稀用漢字を視覚的に似た常用漢字に
  置き換える誤り（`有岡城`→`石岡城`、`殺戮`→`親戮`）が目立った。YomiToku と
  同じ弱点で、こちらもルビ以前に本文の問題

**本文が丸ごとルビと誤判定される事故（読める文章が消える最悪の失敗）は
6冊すべてで起きていない**ことを確認済み。ルビの取りこぼしは劣化だが、
本文の消失は破壊なので、こちらを上位の基準として検証している。

速度は約2.8秒/ページ（12ページ34秒）。詳細は `DESIGN_NDLOCR実装.md`。

#### 節番号が2桁に化ける不具合を修正（v1.11.0）

裸の算用数字で節を区切る本で、**ePubの目次が `11 21 44 66` のように
2桁の数字だらけになる**不具合がありました。

原因は NDLOCR-Lite の認識モデル（PARSEQ）の入力処理です。切り出した行を
**縦横比を無視して**横長の入力寸法へ引き伸ばすため、1文字だけの箱
（節番号の `2` は 26×34px）は横に7倍以上に伸び、同じ字が2度読まれます
（`1`→`11`、`2`→`21`、`4`→`44`、`7`→`17`）。

読んだあとに幾何で弾くようにしました。「1文字ピッチが本文ピッチに対して
小さすぎる」かつ「行方向のインクの塊が1つしかない」行だけを1文字に戻します。
残す1文字は他の認識モデルの読みと確信度から選びます（余計な字は後ろに付く
とは限らず、`7`→`17` のように前に付くことがあるため）。

連帯惑星ピザンの危機（早川書房・371P）で、5章×1〜7の**節番号35個すべてが
正しいラベル**になりました（修正前は23個が検出され、ラベルは全滅）。
本文再現率98.3%・ルビ適合率85.0%は修正前と同じです。

**既存の `_ndlocr.pdf` は誤った文字がテキスト層に焼き込まれている**ので、
症状が出ている本は再OCRが必要です。

#### ダッシュが半角ハイフン1文字になる不具合を修正（v2.1.0）

NDLOCR は縦組みのダッシュ「――」（2セル）を**半角ハイフン `-` 1文字**で
返します。本文の全角の連なりに半角が1字だけ混ざるので、読んでいると
とても目立ちます（『どこよりも遠い場所にいる君へ』で130箇所、
『赤毛のアン』で441箇所）。

対処は2段階です。

**文字の誤り**は jisui2epub 側で直します。和文（かな・カナ・漢字・全角約物）に
挟まれた `-` を全角ダッシュ `―` に置換します。正解テキスト30本を調べた範囲で、
正当な半角ハイフンが和文に挟まれる例は皆無でした（ISBN・電話番号・型番・URLの
ハイフンは必ず英数字に隣接します）。**再OCR済みの `_ndlocr.pdf` をそのまま
変換し直すだけで直ります。**

**字数**は `ndlocr_reocr.py` 側で直します。`-` 1つが1セルの長音なのか2セルの
ダッシュなのかは字面からは決まらないので、印刷を実測します。縦組みでは
ダッシュも長音も細い縦棒なので、**その棒の長さをページの本文ピッチで割れば
何セルぶんかが決まります**。再OCR済み5冊・561箇所で、ダッシュの連続数が
正解と一致したのは **495/510（97.1%）**、長音を誤って伸ばした例は0件でした。
**こちらの効果は再OCRをやり直した本から出ます。**

#### 想定している NDLOCR-Lite のバージョンと、更新時の注意

**動作確認したのは commit `36d7c4d`（2026-08-04）です。**
`ndlocr_reocr.py` は本家のCLI（`src/ocr.py`）を通さず `deim.py` / `parseq.py`
を直接呼ぶため（CLI経由だと1ページごとにモデルを読み直して極端に遅い）、
**本家の内部構造に依存している**。更新する場合は次を確認すること。

| 依存している箇所 | 変わると起きること |
|---|---|
| `src/model/` のモデルファイル名（`parseq-ndl-24x256-30-…` 等の3本） | `load_ndlocr` がファイルを見つけられず起動時にエラー |
| 認識モデルが 30/50/100字級の3本立てであること | `REC_CAPACITY`(25/45/98) と `REC_GEOMETRY_MAX`(22/42) の前提が崩れ、長い列が無言で途中打ち切りになる |
| `config/ndl.yaml` のクラス名（`line_main`・`block_rubi`・`block_pillar` 等） | 本文やルビが丸ごと拾われなくなる（エラーは出ない） |
| DEIM 検出ボックスの膨らみ具合 | `RUBY_INK_RATIO`(0.74) がずれ、隣り合う別語のルビが繋がる／ルビが細くなりすぎる |
| `deim.py` / `parseq.py` のクラス名と `detect()` / `read()` の戻り値 | import 時か実行時にエラー |
| `PARSEQ` の `preprocess` / `session` / `charlist` 属性 | 1文字だけの箱の読み過ぎ補正（v1.11.0）が効かなくなる。例外は握って従来動作に落ちるので、静かに節番号が2桁化する |

**エラーにならず静かに精度が落ちる経路がある**（クラス名の変更・モデル構成の
変更）ので、更新したら必ず数ページ変換して出力を目視すること。
`DESIGN_NDLOCR実装.md` に各定数の実測根拠を残してある。

なお本家の `--det-score-threshold` は `deim.py` で受け取るだけで使われて
いない（効くのは `conf_threshold` のほう）。将来これが修正されると
挙動が変わる可能性がある。

### 画像前処理（v1.6.0〜、既定ON・4バックエンド共通）

OCRにかける前に、スキャン画像を**「本文1文字が32pxになるよう拡縮し、
ガウシアンぼかし（σ1.2）で輪郭を均す」**だけの前処理を自動で適用する。
低解像度でスキャンした本や、走査時に白黒2値化された本で効く。

```bash
# 既定は auto（劣化したスキャンのページだけ自動で適用）
.venv/bin/python yomitoku_reocr.py 本.pdf
.venv/bin/python yomitoku_reocr.py 本.pdf --preprocess off   # 従来動作に戻す
```

実測（YomiToku・本文の文字再現率。手作業校正ePub・公式ePubとの照合）:

| 本 | スキャン | 前処理なし | 前処理あり |
|---|---|---|---|
| はるかなる地球帝国 | 150dpi 濃淡 | 95.56% | **95.93%** |
| ホークミストレス上 | 300dpi 2値 | 97.49% | **97.91%** |
| オルドーンの剣 | 300dpi 2値 | 97.95% | **98.24%** |
| 遠まわりする雛(ノーマル) | 300dpi 2値 | 97.97% | **98.36%** |
| 遠まわりする雛(スーパーファイン) | 600dpi 2値 | 99.51% | 適用対象外 |

ホークミストレス上を1冊まるごと変換した実測では、本文再現率 97.84%→**98.22%**、
ルビの一致も 28.0%→**30.8%** に改善し、処理時間はほぼ変わらない（973秒→974秒）。

**きれいにスキャンできている本には適用されない。** 600dpi相当の本や、
すでに文字が大きく写っている本は前処理しても改善しない（むしろわずかに悪化する）
ことが実測で分かっているため、ページごとに自動で判定して除外する。
1ページおきに画質が変わる本（ScanSnapの両面スキャンは表裏でセンサが別のため
実際に起こる）にも対応している。

Vision / Document AI では、2値化された本にだけ適用される（Vision +0.43pt・
DocAI +0.18pt）。濃淡スキャンでは両者とも改善しないため自動的に見送られる。

なお**超解像AI（Real-ESRGAN）も試したが、単純な拡大＋ぼかしに負けた**
（3モデルすべてで悪化）。潰れた文字を「それらしい別の文字」に描き直して
しまうため。詳しい検証結果は `DESIGN_画像前処理.md` を参照。

### 4つの再OCRバックエンドの選び方

#### まず結論

- **迷ったら `vision_reocr.py`。** 月1000ページ無料で、本文もルビも
  総合的に一番安定している。ただしGoogleアカウント・クレジットカード登録・
  認証JSONの発行が要る
- **クラウドを使いたくない／使えないなら `yomitoku_reocr.py`。**
  現代小説・児童文学なら Vision と互角。**ただし非商用限定**
- **商用利用が必要でオフラインにしたいなら `ndlocr_reocr.py`。**
  本文は実用水準だが**ルビはまだ発展途上**
- **1冊を最高精度で残したいなら `docai_reocr.py`。** 有料だが本文が最も
  きれい。Vision の `--gap-rescue` の相棒としても使う

#### 費用・手間・制約

| | 費用 | 速度 | ネット接続 | アカウント登録 | 商用利用 |
|---|---|---|---|---|---|
| vision_reocr.py | 月1000ページ無料<br>超過 $1.50/1000頁 | 約1秒/頁 | 必要 | GCP＋カード登録 | 可 |
| docai_reocr.py | **無料枠なし**<br>$1.50/1000頁 | 約2秒/頁 | 必要 | GCP＋カード登録 | 可 |
| yomitoku_reocr.py | **無料** | 約2.5〜3秒/頁 | **不要** | **不要** | **不可（非商用のみ）** |
| ndlocr_reocr.py | **無料** | 約2.8秒/頁 | **不要** | **不要** | **可（CC BY 4.0）** |

400ページの本1冊なら、Vision は無料枠内、DocAI は約$0.60、

#### 精度（実測）

| | 本文（児童文学） | ルビ | 時代小説・古典 |
|---|---|---|---|
| vision_reocr.py | 92.6% | **88.8%** | **96.4%（最良）** |

#### 得意・不得意

**vision_reocr.py（Google Cloud Vision）**
- ✅ ルビの再現率が最も高い。時代小説の稀用漢字にも強い
- ✅ 二段OCR（極小ルビの回収）・本文ギャップ救済といった作り込みが最も進んでいる
- ❌ 列頭の1〜3文字を丸ごと返さないことがある（→`--gap-rescue` で DocAI が補う）
- ❌ 1文字だけの極小ルビを検出漏れしやすい（→二段OCRで回収）
- ❌ 挿絵ページでジャンク文字を拾うことがある

**docai_reocr.py（Google Cloud Document AI）**
- ✅ **本文の質が最も高い。** 内容レベルの脱落・化けが少ない
- ✅ Vision が検出漏れする極小ルビを自前で拾える
- ✅ Vision と誤り箇所がほとんど重ならない（校正支援に使える性質）
- ❌ **無料枠が無い。** Vision の約2倍遅い

**yomitoku_reocr.py（YomiToku）**
- ✅ 完全オフライン・無料・登録不要。導入が `pip install` 2行で済む
- ✅ ルビが語単位でまとまって返るので誤結合が起きにくい
- ✅ 挿絵ページでジャンクを返さない。信頼度の低い行を `_lowconf.tsv` に記録
- ❌ **非商用限定（CC BY-NC-SA 4.0）**
- ❌ 時代小説で稀用漢字を似た常用漢字に置換する（`鑓`→`鍵` 等）
- ❌ 縦書きの `」` を `一` と誤認する（対策済みだがこのツール側で吸収している）
- ❌ 濁点の脱落が本文に残る（ルビは自動訂正されるが本文には対策が無い）

**ndlocr_reocr.py（NDLOCR-Lite）**
- ✅ 完全オフライン・無料・登録不要で、**さらに商用利用も可（CC BY 4.0）**
- ✅ 本文は Vision と0.7pt差の実用水準
- ✅ **横書きの本に対応している唯一のバックエンド（v2.5.0〜）**
- ✅ 挿絵ページでジャンクを返さない
- ❌ **ルビが弱い（65〜80%）。** 本家がルビの文字を読まない設計のため、
  切り出しから自作しており発展途上
- ❌ 時代小説の稀用漢字に弱い（YomiToku と同傾向）
- ❌ 導入が3種の中では一番手間（`git clone` が要る・全角パス不可）

#### 併用という選択肢

`vision_reocr.py --gap-rescue auto`（既定）は、Vision が返さない列頭の
断片を検出したページだけ Document AI で読み直して補う。両方の認証を
設定しておくと自動で働く（DocAI 課金は欠落ページのみ＝きれいな本なら0〜3頁）。

## スキャン画質は「スーパーファイン」推奨

同一の裁断済紙本『書を捨てよ、町へ出よう』（角川文庫・320ページ）を ScanSnap の
画質ノーマルとスーパーファインでスキャンし、公式ePub由来のテキストと
文字単位で突き合わせた実測結果:

| 画質 | 文字一致率 | 誤字数（本文約12.9万字中） | PDFサイズ |
|---|---|---|---|
| ノーマル（150dpi） | 95.91% | 5,253字 | 17MB |
| スーパーファイン（300dpi） | **97.65%** | **3,016字（約43%減）** | 39MB |

「い→し」「ン→ソ」「本→木」のような字形混同はスーパーファインでほぼ消える。
ファイルサイズは2.3倍になるが、OCR誤字の校正の手間が大きく減るため
**スーパーファインでのスキャンを推奨**。なお小書き仮名（ツ↔ッ）・半濁点（ボ↔ポ）・
ダッシュ（──→ｌ）の誤りは解像度を上げても残る（OCRエンジン側の限界）。

このうち文脈から機械的に正せるものは内蔵の後処理正規化が自動修正する
（この本では約350〜400箇所/冊）。正規化込みの誤字数はノーマル4,924字・
スーパーファイン**2,634字**まで減る。

**前処理（v1.6.0〜）でも画質差は埋まらない。** 同じ本の300dpi/600dpi版で
比べると、300dpi版に前処理をかけても 97.97%→98.39% にしか届かず、
600dpi版は素で **99.51%**（前処理しても変化なし）。前処理で稼げるのは
画質差の約4分の1で、**取り込み時に画質を上げるほうが圧倒的に効く**。
前処理は「すでに取り込んでしまった本」の救済策と考えてほしい。

## 仕組み

PyMuPDFでOCRテキスト層をスパン（文字＋座標＋フォントサイズ）単位で取得し、

1. 本文フォントサイズを推定（文字数重み付き最頻値）
2. スパンをx座標で縦行にクラスタリング（縦書き前提、右→左）
3. 本文サイズの約半分のスパン＝ルビ候補。y範囲を親行の文字セルに写像して漢字連続にスナップ
4. 本文領域（縦行のy範囲の中央値）の外にある行＝柱・ノンブル候補。
   数字のみ→ノンブル、数字を除いた同一テキストが3ページ以上→柱、として除去
5. 章見出しは「本文より大きいフォント」または「柱と同じテキストがページ右端に深い字下げで現れる行」
   （柱テキスト＝章名の対応を利用。OCR揺れはdifflibのあいまい一致で吸収）
6. 段落は行頭の字下げ量と直前行の短さから復元

横書きモード（`--horizontal`）は、最初にスパン座標を90度転置する（横書きの
「上の行」が縦書きの「右の列」に写るため、ルビ・字下げ・改ページ判定を含む
上記のパイプラインをそのまま流用できる）。段組はスパン段階で「帯」として
検出し（行の左端揃えをクラスタリング）、帯ごとに紙面の左→右の順で処理する。
設計の詳細と実本での検証記録は `DESIGN_横書き対応.md` を参照。

## 実測値（temp_sample の2冊）

- ほんものの魔法使（創元推理文庫・2026年スキャン）: 第1章の文字一致率 **98.1%**、
  全21章の見出しを検出、ルビ208箇所
- グリックの冒険（岩波少年文庫・2013年スキャン）: 全章検出、段落構造は手作業校正版と一致。
  古いOCRはルビ座標が不正確なため、ルビの親文字境界に誤りが出る（`--ruby drop` も検討）

## 限界（残る手作業）

- **OCRの誤認識文字そのもの**（例: フラック→ブラック、レースカバー→レースカゞ〈ｌ）は直せない。
  エディタでの一括置換・校正は引き続き必要（元作業の2〜3割程度）。
  校正後は `--from-text 校正済み.txt` でePubを再生成できる。
  なおルビ内に漢字がまじる誤認識（女《おん姪》等）は、同じ親文字への正常な
  ルビの本内多数決＋類似度で自動訂正される（実測: 霧のむこうのふしぎな町で
  69箇所、誤訂正はいずれも読みの揺れレベル）。濁点・半濁点・小書きの
  誤読（くぴ→くび）も音韻知識＋本内多数決で自動訂正される（4冊実測で
  改善326箇所に対し悪化は正解データ側の誤り6箇所のみ）
- **章題がテキスト層に無い本は章を作れない**（章扉が飾り文字やイラストで、OCR が
  1文字も返さない本がある）。章の位置は改ページとして反映されるが、目次項目には
  ならない。章番号が読めない本では、章の切れ目と場面転換（章の中の空行）を
  組版だけで区別することも原理的にできない
- 表紙・帯・奥付・目次ページはノイズになりやすい（表紙と画像化されたページは
  自動処理されるが、広告など文字の多いページは残る）→ `--pages` で除外するのが手っ取り早い
- 挿絵ページは画像ページ化されるが、本文行が多いと判定されたページのかな入りノイズは残ることがある
- **罫線の無い「文字でできた図」は切り出せない**（v2.3.0）。罫線でつながれた
  系図・表は v2.3.0 で拾えるようになったが、罫線を使わずに配置だけで組んだ
  図（字下げで階層を表す一覧など）は判定の手がかりが無い
- **横書きの本では図のキャプションをテキスト化できない**（v2.2.0）。
  横書きの図解書はキャプションを図の中に組み込むので「図の下の行」という
  構造そのものが無い。キャプションは切り出した画像の中には入っている
- 傍点・圏点・字下げブロックなどの組版情報は検出できない
- 横書きモード（`--horizontal`）は v2.5.0 で図の切り出しと章立てを作り直したが、
  表・脚注・欧文の行末ハイフン結合・複雑な誌面（雑誌型の回り込み）は未対応。
  段組は左端が揃ったレイアウト2〜4段まで。色つき背景ページはスキャナ内蔵OCR
  自体が乱れやすく、ノイズ行が残ることがある。**再OCRで横書きに対応している
  のは `ndlocr_reocr.py` だけ**（vision / docai / yomitoku は縦書き専用のまま）。
  柱欄（ページ端の章題）を章立てに使う「柱ラン」も横書きでは未解禁
- 古いOCR（〜2010年代前半のScanSnap）はルビ精度が低い。`vision_reocr.py` で
  Google Cloud Vision APIによる再OCR後に変換すると精度が上がる
- **`ndlocr_reocr.py`（NDLOCR-Lite）のルビはまだ発展途上**（適合率65〜80%）。
  NDLOCR-Lite はルビの位置だけ返して文字を読まない設計のため、切り出しから
  こちら側の実装になっており、Vision（88.8%）に届いていない。**本文は
  Vision と0.7pt差の実用水準**なので、ルビの少ない本・実用書や、
  商用利用・完全オフラインが要件になる場合の選択肢として位置づけている
- **時代小説・古典はローカル2種（YomiToku / NDLOCR）に向かない。** どちらも
  稀用漢字を視覚的に似た常用漢字に置き換える誤りが出る（`鑓`→`鍵`、
  `有岡城`→`石岡城`）。Vision か Document AI を選ぶこと
- Vision再OCRで行頭の数文字が欠けることがある問題は v1.1.0 の本文ギャップ救済で
  自動回収されるようになった（Document AI未設定の場合は旧OCR文字での補完に
  なるため、まれに化けた文字が残る。ログの「本文ギャップ」行が校正の目印になる）
