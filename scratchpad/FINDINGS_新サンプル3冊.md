| sangoku | 三国志（五）（吉川英治） | 496 | `三国志（五）_GOAL.epub` |

期待値は「ほぼGOALに近く、読書して違和感のない精度」。

## 0. 測定方法

新しく `scratchpad/eval_book.py` を書いた（本1冊まるごとの照合。preproc_lab.py の
採点はページ単位で、章立て・柱の混入まで含めた全体像が見えないため）。

```bash
.venv/bin/python jisui2epub.py <pdf> -o out.txt
.venv/bin/python scratchpad/eval_book.py out.txt <GOAL.epub> --profile
```

- **本文再現率** = GOAL の文字のうち出力側と一致した割合（主指標）
- **挿入率** = 出力側の余分な文字数 ÷ GOAL 長（柱混入・GOAL に無い解説の指標）
- **ルビ適合率** = 出力ルビのうち GOAL のどこかの連続する親片の並びと一致した割合
- **ルビ文字再現率** = GOAL でルビが振られた親文字のうち正しく覆われた割合

全文を difflib に渡すと終わらないので、両側に一意な12-gramで単調な区間に割ってから
区間ごとに `SequenceMatcher` をかける。

### 測定基盤の穴を1つ潰した（重要）

`preproc_lab.py` / 旧 `eval_book.py` の OPF 解析
`id="…"[^>]*href="…"` は **manifest の属性順を仮定していて、`href` が `id` より
前に来る ePub では1件も取れない**。docs が空になりファイル名順のフォールバックに
落ちるので、章順が崩れた GT ができる。百億がまさにこれで、**本文再現率が
73% と出た（正しくは 98.96%）**。両方修正済み。GOAL を新規に足すときは
`eval_book.py` の冒頭数十字が GOAL の冒頭と一致するか必ず確認すること。

## 2. 未着手問題（重い順）

### P1. NDLOCR の重複検出ボックスで柱が二重化し、章見出しがジャンクだらけになる

hyaku p27 の再OCR結果（原本の柱は `第一章影絵の海` 1本・9.5pt）:

```
'第一章影絵の海'  bbox=(42.6,17.0,104.6,32.0) size=12.5
'29影絵の海'      bbox=(29.0,17.0,100.8,32.0) size=12.5   ← 重なっている
'9'               bbox=(32.6,17.2, 45.1,32.2) size=12.5   ← さらに重なる
```

jisui2epub がこれを1行に束ねて `29影絵の海第一章影絵の海` になる。
`norm_hashira` は数字しか落とさないので正規化後も `影絵の海第一章影絵の海` と
**二重のまま**で、柱の頻度カウント（`freq[key] >= 3`）に当たらない。
`classify_marginals` の最後の分岐（jisui2epub.py:691 `size >= body*1.05 or
in_margin`）で見出しに昇格する。

マージン行が重複ボックスを持つページは **hyaku 60/467頁・boku 63/315頁（13〜20%）**。
これが hyaku のジャンク見出し22個、sangoku の51個の正体
（`35　宝剣剣l`・`43　宝剣宝剣`・`411　鴛鴦鴛鴦陣`・`吉吉川川英英治治…`）。

**原因**: `ndlocr_reocr.py` の `_dedup_ruby_boxes`（:213）は
**ルビ箱にしか適用されていない**（:330）。本文・柱の箱は `det.detect()` の
出力をそのまま `lines` に積む（:307-325）。DEIM の NMS（IOU 0.2）はこの重なりを
抑えないことが既にルビ側で判明しているのに、同じ性質が本文側にあることは
見落とされていた。

**対策**: `_dedup_ruby_boxes` を汎用化してクラス内の全ボックスに適用する
（比較はクラス内に限る。line_main と block_pillar は幾何的に重ならない）。
保険として jisui2epub 側で「マージン行の正規化テキストが既知の柱キーを
**部分文字列として**含むなら見出しにしない」を足すと、他バックエンドの
同種の事故も止まる。

### P2. 純漢字の章題が見出しにならず、**本文からも消える**（全経路・データ消失）

sangoku の `荊州往来`・`文武競春`・`一掴三城`・`酔計二花`・`南風北春`・`柳眉剣簪` は
**出力のどこにも存在しない**（ScanSnap で14章題、NDLOCR でも9章題）。

`valid_heading_item`（jisui2epub.py:457）は縦書きではかな・数字を含まない行を
「第N章」等の定型以外は無効とする。ところが無効になった項目は
`page_headings` から外されるだけで `body_lines` には戻らない（:1663）。
**見出しの降格のつもりが削除になっている。** 横書きモードは既に
2〜8字の純漢字を許可する緩和が入っている（:1658-1661）が、縦書きは未対応。

**対策**:
1. まず止血。`valid_heading_item` を落ちた項目は `long_items` と同じく
   本文段落として出す。これだけで「章題が消える」は無くなる
2. その上で、**柱テキストと一致する純漢字は見出しとして許可**する。
   sangoku は柱＝章題なので確実に効く（`matches_hashira` が既にある）

### P3. 3文字以下の章題が見出しにならない

`is_big` は `len(v.cells) >= 4`（:1617）を要求する。sangoku の
`母子草`(3)・`長坂橋`(3)・`大号令`(3)・`月烏賦`(3)・`降参船`(3)・`鴛鴦陣`(3)・
`朝の月`(3)・`裏の裏`(3)・`白羽扇`(3)・`針鼠`(2)・`宝剣`(2)・`舌戦`(2)・
`狂瀾`(2)・`亡流`(2) が全部これで落ちる。本文には
`母《まま》｜子《こ》｜草《ぐさ》` の形で残る（総ルビなので読みは付く）。

**対策**: 「本文比1.25倍以上 **かつ** 柱と一致」なら2〜3字でも許可する。
サイズ単独で緩めると挿絵の飾り文字を拾うので、柱一致を必須にするのが安全。

### P4. 章番号が挿絵ページの囲み数字にある本は章立てが全滅する

boku は15章すべてが「全面挿絵＋右上の囲み数字」で始まる。

- ScanSnap は囲み数字を**1つも読まない**（該当ページのテキスト層は
  ノンブルと記号ノイズだけ）
- NDLOCR は読むが囲み枠を巻き込む: `2)`・`□□`・`1,,00`・`10`・`00`・
  `717`・`11`・`14`・`15`。14ページ中まともなのは6〜7
- さらに画像ページ上の見出しは `matches_hashira` か `_single_chapter_heading` しか
  通さない（:1686-1688）ので、読めても採用されない（柱は書名なので一致しない）

**対策**: 読めた数字を信用しない方向で。「本文0行＋孤立した短い数字列」の画像ページが
書籍内に3件以上・ほぼ等間隔で現れるなら**章頭画像**とみなし、
**出現順で連番を振る**（`1`〜`15`）。GOAL の nav がまさに `1`〜`15` なので、
数字を読めなくても正解に一致する。DESIGN_章頭改ページ.md の
y0クラスタ方式（同じ位置に繰り返し現れることを採用根拠にする）と同じ考え方を
「ページ内位置」でなく「巻内の出現間隔」に適用する形。

### P5. 再OCR済みPDFで書字方向の誤警告が出る

3冊とも `警告: 横書きの本の可能性があります（向き票: 横 289 / 縦 0 文字）` が出る。
縦書きの本なので誤り。**`--horizontal` を付けると全損**なので実害がある。

原因は `span_is_vertical` が1文字スパンで `None` を返すこと。再OCR経路は
本文を1文字ずつ `insert_text` するため縦書き側の票は常に0で、票を持つのは
**柱・ノンブルの横書きスパンだけ**になる。NDLOCR 固有ではなく
`黒牢城_米澤穂信_vision.pdf` でも再現する（縦2 / 横534）。

**対策**: 1文字スパンの比率が高いPDFでは判定自体を抑止する（票が
「柱・ノンブルしかない」状態を検出する）。CLAUDE.md の
「旧OCRでは票が集まらないため自動切替しない」は**再OCR済みPDFにも当てはまる**。

### P6. 柱・ノンブルを本文サイズで書き戻すので「マージン内の小さい文字＝柱」が効かない

原本の柱は 9.5pt / 本文 12.5pt。NDLOCR 経路では柱も 12.5pt になるため、
`classify_marginals` の `in_margin and size < body*0.95`（:686）が空振りする。
現状は頻度一致（:682）が救っているだけで、P1 で頻度が効かなくなると
そのまま見出しに落ちる。

**NDLOCR は柱・ノンブルを `block_pillar` / `block_folio` として分類して返している**
のに、`ndlocr_reocr.py` はその区別を捨てて全部 `target_body_fontsize` で
書き戻している（:64, :317, :503）。

**対策**: `MARGIN_CLASSES` は実測サイズ（または body×0.75）で書き戻す。
P1 と合わせれば柱除去は素の ScanSnap 並みに戻る。ルビ判定（0.68倍）への
巻き込みが心配なら 0.75倍に留めればよい。

### P7. hyaku でだけ NDLOCR のルビが悪化する（69.0% → 54.6%）→ 調査済み・一部修正

**「ルビ処理の不備」と「本文OCRの弱点」が混ざっていた。**

**(1) 読みか紐付けか**: 書き戻し後のPDFから**ルビの読みだけ**を取り出して
GOAL 辞書で採点すると（親への紐付けを通さない）、百億 p130-160 で
素 186語/72.6% に対し **NDLOCR 228語/74.1%**。**読みだけなら NDLOCR が上**。
一方「読みが正しいペアの親正解率」は素 96.4% に対し NDLOCR 83.2%。
損失は紐付け側にある。

**(2) 親を外す原因の内訳**（`scratchpad/attach_acc2.py`、本全体）:

| | 百億 素 | 百億 NDL | 三国志 素 | 三国志 NDL |
|---|---|---|---|---|
| 正解 | 69.0% | 54.6% | 54.8% | 74.2% |
| 読み自体が誤り | 28.4% | **34.4%** | 23.8% | **9.3%** |
| 親のOCR誤り | 1.0% | **6.9%** | 12.4% | 8.0% |
| 親の範囲ずれ | 1.2% | 2.9% | 1.2% | 2.3% |
| まったく別の親 | 0.3% | 1.2% | 7.8% | 6.3% |

百億の -14.4pt は**読みの誤り +6.0pt と親のOCR誤り +5.9pt でほぼ全部**。
「親のOCR誤り」は `悉達多→恭達多`・`楼那→四楼`・`夜摩天→夜摩大`・
`四王天→四工天`・`日月星辰→日月足辰` で、**天→大・王→工 の字形置換**。
CLAUDE.md の YomiToku「稀用漢字を似た常用漢字に置換する」と同型で、
**ルビ処理では直せない**（百億の本文再現率が唯一 素に負けるのも同じ原因）。
三国志で NDLOCR が勝つのは読みの誤りを 23.8→9.3% に減らすからで、
こちらが本来の実力。

**(3) 直せた部分（実装済み）**: ルビ箱が複数語をまたぐとき
`_split_ruby_runs` が切れない。原因は**インク判定が「1画素でも暗ければ」**で、
語間の余白に散るスキャンノイズで空白が分断されること（p135 実測: 語間の
連続空白が1画素判定で35px、2画素以上なら79px。min_gap 37px）。
`RUBY_INK_MIN_FRAC`=0.08 と `RUBY_GAP_RATIO` 1.0→1.2 に変更（3冊×30ページの
格子探索で3冊とも悪化しない組み合わせを選択）。

| ルビ適合率 / 文字再現率 | 修正前 | 修正後 |
|---|---|---|
| 百億 | 54.6% / 47.7% | **63.8% / 60.9%** |
| ぼく | 85.8% / 78.2% | 86.8% / 81.1% |
| 三国志 | 74.2% / 59.6% | 74.5% / 60.1% |

本文再現率・章立ては3冊とも不変。dedup が小箱を飲み込む件（大箱1つが5語を
覆い `諸法無我《あるこの》` になる）も、**発生率は3冊とも7〜8%で百億固有では
なく**、この分割修正で大箱が正しく5語に切れるようになったため個別対処は不要。

**残り**: 百億は素の 69.0% にまだ届かない（63.8%）。残差は親のOCR誤り 8.4%
と読み誤り 24.8% で、どちらも NDLOCR の認識能力そのもの。
**外来語カタカナルビ＋梵語＋固有名詞が重なる本は Vision を選ぶのが正解**。
