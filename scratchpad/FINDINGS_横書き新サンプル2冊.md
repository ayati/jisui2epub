対象（いずれも講談社ブルーバックス・横書き・NDLOCR再OCR版を入力）:

| 本 | 入力PDF | 頁 | GOAL ePub |
|---|---|---|---|
| ネットオーディオのすすめ | `…_山之内正_ndlocr.pdf` | 223 | 24.5MB / 図106枚 / nav 18項目 |
| 楽器の科学 | `楽器の科学_…_ndlocr.pdf` | 242 | 16.0MB / 図64枚 / nav 13項目 |

いずれも `--orientation auto` が横書きを正しく判定（横票率 1.00）。
書誌（ISBN・NDL・刊行日・叢書名）は2冊とも完全に取れている。

## 0. 【最優先・計測基盤のバグ】eval_book.py のアンカー鎖が貪欲で壊れる

`anchors()` の「単調増加の最長部分列（貪欲）」は first-fit なので、
**早い位置に紛れ込んだ1個の逆順アンカーで鎖全体が汚染される**。
ネットオーディオでは gt 3267 の直後に hyp 79695 が採られ、以降7万字が
一切照合されず **本文再現率が 6.54% と出た**（正しくは 96.65%）。

厳密な LIS（patience sorting）に替えるだけで直る。
検証版は `scratchpad/eval2.py`（`eval_book` を import して `anchors` を差し替え）。
**この誤差は「ツールが壊れた」と誤読させる**ので最優先で本体に取り込むこと。

## 2. 問題点（効果の大きい順）

### 2.1 巻末（索引・奥付・巻末広告）が本文に流れ込む — 挿入の6割

`detect_body_end` は `horizontal=True` で無条件に `None` を返す（既定仕様）。
横書き用の `detect_body_end_h` と `detect_index_pages` は**存在するが、
図の切り出しを止めるためだけに使われている**（`jisui2epub.py:3388-3396`）。
テキストと見出しには一切効かない。

実測（`detect_index_pages` の出力は正しい）:

- ネットオーディオ: 索引 = 物理 202,203,205,208-212,216 を検出。`detect_body_end_h` は **None**
- 楽器の科学: 索引 = 物理 233-238 を検出。`detect_body_end_h` = 239（正しい）

結果、出力の**末尾 594行／2430行（24%）が索引・奥付・ブルーバックス既刊広告**になり、
段組広告のOCRジャンクがそのまま本文と見出しになる:

```
［＃「ブルーバックスB-2272」は中見出し］
［＃「70科意「日理」は中見出し］
［＃「カPy田ンならの松の技」は中見出し］
```

**さくいん行で機械的に切っただけの効果（実測）**:

| | 挿入率 | 本文再現率 | ルビ誤検出 |
|---|---|---|---|
| ネットオーディオ 現行 → 切断 | 18.74% → **10.72%** | 96.65 → 96.57%（−0.08pt） | 38 → 7 |
| 楽器の科学 現行 → 切断 | 8.12% → **3.08%** | 98.35 → 98.25%（−0.10pt） | 変化なし |

改善案: `index_pages` と `detect_body_end_h` を `assemble_text` の
`body_end` 相当として渡す。少なくとも**見出しの発行を止める**だけでも
nav の後半20項目のジャンクが消える。`detect_body_end_h` が None を返す
ネットオーディオは、`detect_index_pages` の最小ページ以降を後付けと
みなせば足りる（索引より後ろに本文が来る本は無い）。

### 2.2 本文ページが「印刷目次」と誤判定されて画像化＝本文が消える（楽器の科学）

`detect_toc_pages` が **p15 を目次ページと誤判定**し、画像化して
**プレリュード章の冒頭 約580字＋章題2本が丸ごと消えた**
（出力は目次画像6枚のあと `継がれた楽曲や、…` と文の途中から始まる）。

実測値:

```
p10: entries=12 kana=0.126 pair=True  tail=[0,13,330,32,34,36,41]   ← 真の目次
p14: entries=14 kana=0.059 pair=True  tail=[100,3,182,184,187,…]    ← 真の目次
p15: entries=25 kana=0.378 pair=False tail=[0]                       ← 本文（誤判定）
p16: entries=26 kana=0.513 pair=False tail=[]                        ← 本文（正しく除外）
```

2つの門が両方すり抜けている:

1. `TOC_PAGE_KANA_MAX`=0.40 に対し p15 は **0.378**。飾り帯のOCR
   `thethethethethe…` がかな率を押し下げた（p16以降の本文は 0.45〜0.57）
2. 隣接規則の歯止め「行末の数字が1つも無いページは目次の続きにしない」は
   **`tail` が空でないことしか見ない**。p15 は誤読の `0` が1個あるだけで通る

改善案: 隣接規則の `_toc_tail_numbers` に**下限（>=3程度）**を課す。
実測の真の目次ページは 5〜11 個、p15 は 1 個なので明確に分かれる。
`_toc_pair_signal` が要求する `TOC_PAIR_MIN_LINES` と揃えるのが素直。

### 2.3 印刷目次を画像化しても、その断片が章題辞書を汚して本文の見出しを壊す

ネットオーディオの印刷目次は
`… 小型化のデメリットはないのか？58/オーディオの新常識--機能の集約化59/…`
という「項目 ページ数 / 項目 ページ数」の1行組み。目次ページ自体は
正しく画像化されているが、**帯分割された断片が `_TOC_MULTI_ITEM_RE`
（`/` が2つ以上）をすり抜けて章題辞書に入り**、本文側の正しい見出しを
上書きする。実測で5件:

| 出力（現行） | 正しい見出し |
|---|---|
| `型化のデメリットはないのか？58/オーディオの新` | 小型化のデメリットはないのか？ |
| `ク』の再生方法78/楽曲情報` | 『アップル ミュージック』の再生方法 |
| `その4各種ストリーミングサービスへの対応93/` | 【選び方その4】各種ストリーミングサービスへの対応 |
| `ンミュージック』固有の設定192/空間オーディオと` | 『アマゾンミュージック』固有の設定 |
| `ころ・聴きどころ198/世界最高水準の音質を実現` | 『STAGE+』の見どころ・聴きどころ |

`--no-toc-refine` を付けると5件すべて正しい見出しに戻る（実測で確認）。
見出し一致数は 70 → 69 とほぼ同じなので、**この本では目次照合が
差し引きゼロ〜マイナス**。

改善案: 目次エントリの採用条件に「行末のページ数を剥がした残りだけを
辞書に入れる」「ページ数が行の途中に現れる行は辞書に入れない」を足す。
`_TOC_MULTI_ITEM_RE` を「`/` が1つ以上、または行中に1〜3桁の数字がある」に
締めるだけでも5件とも落ちる。

### 2.4 章立てが実質できていない（両書とも）

**楽器の科学（5章中 正しい章題 0）**

| GOAL | 出力 |
|---|---|
| 第1楽章 作曲の「かけ算」を支える楽器たち | `第楽章　作曲の「かけ算」を　支える楽器たち　―…`（番号欠落） |
| 第2楽章 楽器の個性は「倍音」で決まる | `「倍音」で決まる`（2行組みが分割・番号欠落） |
| 第3楽章 楽器の音色は「共鳴」が美しくする | `「共鳴」が美しくする`（同上） |
| 第4楽章 「楽器の最高性能」を引き出す空間とは？ | `第一楽章　楽器の最高性能」を　引き出す…`（番号誤り） |
| 第5楽章 演奏の極意 | `演奏の極意　―世界的ソリスト10人が…`（番号欠落）＋ `演奏の極意第楽章ehteht` の重複 |

原因は3つ:

- **番号欠落・誤りはOCR側**（PDFのテキスト層自体が p23 `第楽章`、
  p132 `第一楽章`）。印刷目次側も `2.章楽第一楽器の個性は…` と崩れており、
  `refine_headings_with_toc` では直せない。
  → `detect_toc_chapter_pages`（目次のページ数→物理ページ）の横書き版が要る
- **2行組みの章題が分割される**。`DESIGN_横書き章立て.md` の
  「見出しはページ先頭にまとめず読み順で出す」判断の副作用。
  飾り帯の章扉は `第2楽章 楽器の個性は` ／ `「倍音」で決まる` の2行なので、
  読み順に別々の見出しとして出ると章題が半分になる
- 節見出し `1-1`〜`1-6` は `１　-3膜鳴楽器` のように**番号と題のあいだに
  全角空白が入り、ハイフンが題側に付く**

**ネットオーディオ（10章すべて `第N章` の接頭辞が消える）**

`第3章 再生機器の変化と進化` が `再生機器の変化と進化` になる。
この本の**柱が `第N章 章題` そのもの**（p81 の柱 = `第4章ストリーミング
サービスの選び方`、本文12.0ptに対し柱15.6pt）なので、
`HASHIRA_FUZZY`（現在は横書き限定で有効）を章題辞書として使えば復元できる。
さらに `第10章ネットオーディオとは？`（第1章の章題が第10章に付いた）という
明確な誤りが1件出ている。

**部扉が消える**: `第1部 ネットオーディオのすすめ` / `第2部 クイック・
スタート・ガイド` は画像ページになりテキストが残らない（GOAL nav にはある）。

### 2.5 nav が2階層にならない（`_group_section_episodes` が不発）

`_CHAPTER_TITLE_RE = 第[0-9０-９一二三四五六七八九十]{1,3}章` は
リテラルの「章」しか受けない。

- 楽器の科学は `第N楽章` → 一致0件 → **nav 168項目がフラット**（GOAL 13）
- ネットオーディオは 2.4 のとおり `第N章` が剥がれている → 一致1件（3未満）
  → **nav 128項目がフラット**（GOAL 18）

改善案: (a) 正規表現を `第N(章|部|楽章|編|話|幕)` 等に広げる、
(b) 横書きの `N-N` 形式の節番号（`1-1`〜`5-1`）も章の単位として扱う、
(c) 2.4 で `第N章` を復元すればネットオーディオは自動的に直る。
GOAL の nav は「部＋章」だけの18項目なので、**3階層（部＞章＞節）**に
できるとなお良い。

### 2.6 図の適合率が低い（楽器の科学 43.6%）

**(a) 飾り帯の節見出しが図として切り出され、見出しが消える**

`1-2 体鳴楽器 idiophone：イディオフォン` のような節見出しは飾り罫つきの
帯なので図として検出される。`FIG_HEAD_COVER_RATIO` の救済
（`jisui2epub.py:3161-3165`）は

```python
kana = len(_HIRAGANA_RE.findall(t))
if (_line_text_size(v) >= body_size * FIG_HEAD_COVER_RATIO
        and len(v.cells) >= 4
        and kana >= 3 and kana >= len(t) * 0.2   # ← ここで落ちる
        and valid_heading_item(t)):
```

**`1-2 体鳴楽器` はひらがな0字**なので救済されず、帯ごと図になる。
実測で 1-2 / 1-4 / 1-5 の3節見出しが画像化され、nav から消えた。
`DESIGN_部分図.md` §15 の「ひらがな3字以上かつ2割以上」は
図解・気象学入門の口語的な小見出し向けの条件で、**漢語の節見出しを
持つ本には効かない**。`matches_hashira` 一致か「数字＋漢語」の形なら
かな条件を免除する、といった緩和が要る（縦書きの
`valid_heading_item` が「2〜8字の純漢字」を横書きで追加許可しているのと同じ発想）。

**(b) 本文がそのまま図になる**

実測（目視確認）:

- 楽器の科学 p33 `楽器例：ガラガラ（ラットル）、鈴、マラカス、…` の2行が図に
- ネットオーディオ p47 `①非圧縮音声データ ②可逆圧縮音声データ …` の箇条書きが図に
- ネットオーディオ p55 `自分のニーズを具体的に考えてみましょう。/ 判断の基準として…` が図に

**テキストは消えない**（`--inline-figure off` との本文diffは2冊とも0行）ので
実害は ePub の肥大と重複表示だけだが、適合率を大きく下げている。
いずれも「飾り罫・飾り帯で囲まれた短い本文ブロック」で、
`_fig_ladder_lines` の梯子から外れるのが原因。

**(c) 巻末索引・広告のページから図を切り出す**

`detect_index_pages` は効いているが `detect_body_end_h` が None のため、
ネットオーディオは物理 218〜224 の広告ページから図を10枚以上切り出す。
2.1 を直せば同時に消える。

### 2.7 図中・スクリーンショット中の文字が本文に流れ込む

GOAL は図・表・画面写真の文字を画像の中にしか持たないが、こちらは
テキスト層にあるものを全部本文に出す。挿入の主要因の2つめ:

- Amazon Music / Roon の設定画面のOCR（1件で230〜290字。
  `定設登録を管理不適切な歌詞を含む楽曲の再生を制御スリープタイマー…`）
- 表のセル（`表2-1 代表的な音声ファイルフォーマット` で703字、
  `基準音の一覧` で142字）
- 図キャプション（`図1-1パッケージメディアはエジソンの蝋管蓄音機から…`）。
  横書きは `--figure-caption` の対象外なので `<figcaption>` にならず
  地の文に混ざる。**14本がそのまま中見出しに昇格**している
  （`図1-2ネットワークプレーヤーの例LUMIND3` など）

改善案（重い順に検討価値あり）:
1. `◆図N-N` / `図N-N` / `表N-N` で始まる行は**見出しにしない**（低リスク・即効）
2. 切り出した図の矩形に完全に含まれる行は本文から落とすオプション
   （`--figure-text {keep,drop}`。既定 keep で非回帰）
3. 横書きでも `<figcaption>` に回す（キャプション行の判定は
   「図/表 + 数字」の署名が横書き実用書では使える。
   `DESIGN_部分図.md` §14.6 が「使えない」としたのは
   星空・蘇我氏＝縦組みの写真キャプションの話で、この2冊には当てはまらない）

### 2.8 ルビの誤検出（横書き）

ネットオーディオは GOAL 4組に対し出力 38組（適合率 0.0%）。
巻末を切ると7組まで減るが、残るのも図中の小活字:

```
のネットワーク設《タスクが一時停止されます》
◆図《キャッシュディレクトリのパス》
図《コンサート映像》
```

**読みが14字**のルビは日本語に存在しない。
`読み ≤ 親字数×4 かつ ≤10字` 程度の上限を置けば全部落ちる（副作用なし）。
楽器の科学のルビは 75組・適合率76.0% と実用的なので、
横書きでも `--ruby drop` を既定にする必要はない。

### 2.9 その他（小さいが確認済み）

- **濁点・小書きの脱落は未対策**（`筐体《きようたい》`＝`きょうたい`）。
  `normalize_ocr_text` は「小書き→並字」しか持たず逆方向が無い。
  ルビは `fix_ruby_variants` が本内多数決で直すが、1回しか出ない語は直らない。
  実測は 濁点 net 15 / gakki 55、小書き net 3 / gakki 10 と少数
- 前付けの `第1部` `第一楽章` 扉ページが画像化されテキストが残らない
- ネットオーディオ第1章は章扉が本文と同じページ（p16 = `第章 /
  ネットオーディオとは？ / ■音楽再生の環境は…`）なので、
  章題が本文行に埋もれて見出しにならない
- ePub サイズは GOAL より小さい（9.8MB 対 24.5MB / 7.7MB 対 16.0MB）。
  `--figure-dpi 216` は妥当

## 4. 実装した修正（2026-09-06）

効果の大きい4件を入れた。**ルビだけは提案どおりの「10字上限」を採らなかった**
（4.4）。回帰は `scratchpad/reg_backmatter.sh`（baseline / new / diff。
横書き9冊＋縦書き25冊）。

### 4.1 巻末（索引・奥付・巻末広告）を本文ごと落とす（横書き限定）

`detect_backmatter_h` を新設し、`assemble_text` に `backmatter_pages` を追加。
**見出しだけでなく本文行も出さない**（縦組みは従来どおり `body_end` で
見出しだけを止める）。全面画像ページだけは図タグとして残す
（「発刊のことば」「裏表紙」は絵として意味がある）。
`--no-backmatter-cut` で無効化できる。

**切るのは「最後に本文らしいページが出た次」で、索引の先頭ではない。**
最初は `min(detect_index_pages())` で切ったが、**シナリオのための
ファンタジー事典は p294-297 に索引があり、そのあと p299-345 に本文が
47ページ続く**（居酒屋・ギルド・商人・職人・医療・旅）。索引で切ると
見出し17本・本文1194行が丸ごと消えた。索引が巻末にあるとは限らない。

しきい値は書籍ごとに決める（`BACKMATTER_BODY_RATIO`=0.5＝「版面いっぱいの行」の
本数の中央値の半分）。実測は本文ページ 11〜23 に対し後付け 0〜6
（奥付5・裏表紙6）で、**固定値では分けられない**。
歯止めは本の末尾15%（`BACKMATTER_H_TAIL`）。

### 4.2 目次の隣接規則に行末ページ数の下限（`TOC_ADJ_TAIL_MIN`=3）

「行末の数字が1つも無いページは目次の続きにしない」を「3本に満たないページは
目次の続きにしない」に締めた。楽器の科学 p15（プレリュード章の冒頭）は誤読の
`0` が1本あるだけで目次扱いされ画像化されていた。**本文580字と章題2本が復活**
（`楽譜──音楽を「科学」へと進化させたもの` が nav に戻った）。
真の目次ページは行末のページ数が 5〜11 本で、1本とは離れている。

### 4.3 図・表のキャプションを見出しにしない（`_FIG_CAPTION_RE`・横書き限定）

`図N-N…` `◆図N-N…` `表N-N…` `写真N-N…` で始まる行を横書きの見出し候補から外す。
**番号が「N-N」の形のものだけ**を落とすので、`図解` のように数字を伴わない語や
`1-1 楽器を分類する科学` のような本物の節見出しには触れない。
ネットオーディオで誤見出し14本が消え、副産物として偽の見出しで2つに割れて
いた段落がつながった。

### 4.4 ルビの組の妥当性判定 — 「10字上限」は**不採用**

**提案どおりの字数上限は採れない。** temp_sample の GOAL ePub 41冊・
ルビ 101,996 組を実測した結果:

| 読みの長さ | 組数 | 累積 |
|---|---|---|
| 〜3字 | 99,592 | 97.6% |
| 4〜9字 | 2,363 | 99.96% |
| **10字以上** | **41** | 100% |

10字を超える正当なルビが **32組**ある:

```
國鉄特別強襲班《こくてつとくべつきょうしゅうはん》  16字
二次代謝調節機構《サイド・メタボライザー・システム》 16字
図書特殊部隊《ライブラリー・タスクフオース》        14字
釣浮草《レデイーズ・イア・ドロツプス》              14字
```

**読み／親字数の比の上限も置けない**＝`び《プッシュジャンパー》` の 9.0 が
正当なうえ、OCRがルビを2語つないでしまった形（蘇我氏の
`元明《やまとねこあまつみしろとよくになりひめげんめい》` 比12）は
**読みとしては正しい情報**なので落としたくない。

実測で**正当なルビを1組も切らない**署名は **「読みに漢字が2字以上」だけ**
（101,996組中 **0組**。漢字1字は11組あるがいずれもGOAL側の変換残骸）。
これを `ruby_pair_ok` / `drop_bogus_rubies` として実装した。

掛ける場所に2つの制約があり、**どちらも実測で踏んだ**:

1. **`fix_ruby_kanji` より後**。`render_vline` で捨てた版では、あちらが本内
   多数決で直せるはずの漢字混入ルビ（霧の `魔術師《坐壬じゆつし》` →
   `魔術師《まじゅつし》`）を先に消し、**31冊 254組**のルビが失われた
   （`台所《だいどころ》`×6・`隙間《すきま》`・`医師《メディクス》`・
   `徐庶《じょしよ》` 等の正当なルビを多数含む）
2. **底本の literal な `《》` に触らない**。引用符として `《》` を使う本があり
   （人類の起源の `ゴーギャン作《我々はどこから来たのか、我々は何者か、
   我々はどこへ行くのか》`）、テキストだけを見ると誤付着ルビと**区別できない**。
   分かるのは幾何だけなので、`render_vline` が実際にルビとして書いた組
   （`ruby_pairs_out`）に限って落とす

さらに、読みの正規表現は**改行をまたがせず長さ上限を置く**
（`_RUBY_DROP_RE`）。`_RUBY_PAIR_RE` の `《[^《》]+》` をそのまま使うと、
OCRノイズの迷子の `《` とはるか先の `》` が対応して**本文を丸ごと巻き込む**
（人類の起源 p180 で本文20行が消えた）。

実測: 縦書き25冊で落ちるのは78組で**全部ジャンク**（章見出し数は全冊不変）。
ネットオーディオは 38→5 組。`魅《ールズ》`・`値《する》` のような短い誤ルビは
どんな規則でも正当なルビと分けられない。
